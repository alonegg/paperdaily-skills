# 精读笔记模板

适用阶段：Stage 3（深度分析）单篇精读。输出文件：`notes/<paper_id>.md`。

## paper_id 命名规则

跨 `notes/`、`claims.jsonl`、`report.md` 三处必须使用同一个 id：

1. **走完整流水线（有 worklist.jsonl）时，paper_id = worklist 行的 `id`
   字段原样**（如 `arxiv:2409.10897`、`W4416083181`、期刊 stub id），
   这是阶段 1→3 的全流程主键。对应 PDF 文件名是它的安全化形式
   （非 `[A-Za-z0-9._-]` 字符替换成 `_`，即 `arxiv:2409.10897` →
   `pdfs/arxiv_2409.10897.pdf`）；笔记文件名同用安全化形式
   `notes/arxiv_2409.10897.md`，笔记正文的 **paper_id** 字段写原始 id。
2. 用户自带 PDF、没有 worklist 时的兜底：有 arXiv ID → `arxiv:<裸号>`；
   否则有 DOI → `/` 替换成 `_`（如 `10.1145_3600006`）；否则
   `<第一作者姓，小写><年份>_<标题前3个实词 slug>`。

一旦为某篇论文定下 id，全程复用，不要中途改写法。

**`**paper_id**:` 那一行只能有 id 本身，说明文字另起一行。** 上传闸门用正则
取这一行的反引号内容，反引号后面追加"（工作论文版，非 RFS 正刊）"这类给人看的
注解会让整批笔记在 dry-run 被拦下。要写的话写成下一行的普通文字：

```markdown
- **paper_id**: `hhag020`
  取自 2021 NZFM 会议工作论文版，与 RFS 正刊版页码不一致。
```

## 版本铁律（0.5.0）

获取层可能拿回**同一篇论文的另一个版本**——工作论文、会议稿、作者主页稿。
`fetch_report.jsonl` 会用 `version: "alternate"` 标出来，并给出 `matched_title`。
这不是瑕疵（多数情况下这是唯一拿得到的全文），但**页码、样本量、表号在版本
之间不通用**。所以：

- Metadata 的 **版本** 字段如实填，不要默认写 vor；
- 笔记正文第一段注明读的是哪一版、与目标 DOI 的关系；
- 综合阶段引用具体数字时，如果该数字来自 alternate 版本，claims 里要说明——
  拿工作论文的样本量去描述正刊结论是实打实的错误陈述。

## 操作规程

1. **先扫结构，再精读。** 第一遍只读 abstract、intro 最后一段（通常是贡献列表）、conclusion、所有图表标题，5 分钟内建立论文骨架（做什么 / 怎么做 / 结论是什么），据此决定精读顺序和重点。
2. **图表公式随读随记，不单开章节。** 读到某个图/表/公式时，直接把它写进正文对应支撑的字段里（通常落在 Methodology 或"实验结果分析"），不要攒到最后统一写一个"图表"章节——脱离上下文写图表说明，锚点最容易记错、结论最容易脱离原始限定条件。
3. **每写一个字段，立刻标位置。** 不要等笔记写完再回填页码，回填时几乎必然是凭印象编造锚点。
4. **QA 对留到最后。** 通读完成后回看笔记全文，挑读者自己重新查证才能回答的问题——不是摘要一句话就能答的（信息熵低），而是需要理解方法细节 / 实验设置 / 隐含假设才能答的。

## 锚定铁律

**每个字段必须写清楚信息来自 PDF 的具体位置**，不能写"论文说""作者认为"这类无锚定表述。统一锚定格式：

- `(p.X)` — 页码
- `(p.X, Fig.Y)` — 页码 + 图号
- `(p.X, Table.Y)` — 页码 + 表号
- `(§N.M)` — 章节号（连页码都定位不到时的最低要求）

找不到具体页码时至少给章节号；绝不允许无锚定字段——宁可写"未在文中明确说明"，也不能编造锚点或凭记忆转述。

**页码从哪来是这条铁律的前提**：必须用保留分页信息的方式读 PDF（Read 工具带 `pages` 参数，或 `pdftotext -layout` 数换页符 `\f`），页码一律用物理页而非印刷页。读法、降级规则、物理/印刷页基准的写法见 [deep-read-agent-prompt.md](deep-read-agent-prompt.md) §1——用丢掉分页的方式读完再回填页码，等于在编造锚点。

## 三个降级标记（写在 Metadata，下游要读）

| 标记 | 什么时候用 | 后果 |
|---|---|---|
| `abstract-only` | 阶段 2 没取到全文，只有摘要 | 只填摘要能确证的字段；阶段 4 回传时 depth 记为 abstract-only |
| `anchor-degraded` | PDF 读得到但拿不到可靠页码（加密/扫描件/工具报错） | 全篇改用 `(§N.M)` 章节锚 |
| `PDF 页码基准: 物理 p.1 = 印刷 p.<N>` | 印刷页码与物理页码不一致 | 声明一次，全篇按物理页锚定 |

降级本身不丢人，**不声明降级才是问题**——阶段 4 的 depth 推断和 claims 的证据强度都靠这些标记，冒充全文级会让整条证据链失真。

## 模板（复制到 `notes/<paper_id>.md`）

```markdown
# <论文标题>

## Metadata
- **作者**: <姓名列表>
- **年份**: <YYYY>
- **Venue**: <会议/期刊名，或 "arXiv preprint" / "未发表">
- **DOI**: <DOI 或 "无">
- **代码仓库**: <URL 或 "未开源">
- **paper_id**: `<paper_id>`
- **PDF 来源**: <本地路径或获取渠道，参见 fulltext-sources.md>
- **全文载体**: <binary-pdf / html-fulltext / parsed-fulltext>
- **版本**: <vor 正式发表版 / accepted 录用稿 / wp 工作论文 / preprint / alternate；
  取自 fetch_report.jsonl 的 `version` 字段，没有该字段写 unknown>
- **读取方式**: <Read pages=1-14 / pdftotext -layout>
- **降级标记**: <无；或按上表填写降级标记与页码基准，见「三个降级标记」>

## Problem
<一句话说清这篇论文要解决什么问题> (p.X)

## Key Contributions
1. <贡献 1> (p.X)
2. <贡献 2> (p.X)
3. <贡献 N> (p.X)

## Methodology
- **方法类型**: <如：监督微调 / 强化学习 / 检索增强 / 理论证明 / 实证研究 / 因果推断...>
- **核心思路**: <一段话，方法的核心 insight> (p.X, §N)
- **关键组件**: <逐项列出，各自锚定，如模型结构 / 损失函数 / 算法步骤 / 识别策略> (p.X, Fig.Y)
- **与前人差异**: <这篇方法和它明确对比或继承的前人方法相比，具体不同在哪> (p.X)

## 数据与实验设置
- **数据集**: <名称 + 规模 + 来源> (p.X, Table.Y)
- **基线 (baselines)**: <对比方法列表> (p.X)
- **指标**: <评价指标定义> (p.X)

## 实验结果分析
- **主要定量结果**: <关键数字，及与最强基线的差距> (p.X, Table.Y)
- **消融发现**: <去掉哪个组件、掉了多少> (p.X, Table.Z)

## Limitations
- **作者自陈**: <论文 Limitations/Discussion 章节的概括，不是转述摘要> (p.X, §N)
- **读者观察**: <读者自己发现但作者未提及的局限，如数据集覆盖面、统计显著性、复现难度、外部效度>

## Connections
- **建立在哪些工作上**: <逐条列出关键前驱工作及具体继承关系> (p.X, §Related Work)
- **相关工作定位**: <作者如何把这篇论文和同期工作区分开>

## QA（5-7 个信息熵最高的问答对）
1. **Q**: <问题，要求读过方法细节才能答> **A**: <答案> (p.X)
2. **Q**: ... **A**: ... (p.X)
3. **Q**: ... **A**: ... (p.X)
4. **Q**: ... **A**: ... (p.X)
5. **Q**: ... **A**: ... (p.X)
```
