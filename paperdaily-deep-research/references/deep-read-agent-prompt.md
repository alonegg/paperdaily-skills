# 阶段 3a 派工规程：怎么读 PDF、怎么派子 agent、子 agent 回什么

适用阶段：Stage 3a（逐篇精读 fan-out）。本文件解决三件在实跑里最容易翻车的事：
**页码从哪来**、**主 agent 派工说什么**、**子 agent 回传什么**。

阶段 3 是整条流水线里最贵的一段（每篇一个子 agent、每个子 agent 读一整篇论文），
也是唯一没有脚本兜底的一段——质量全靠派工说清楚。所以这份规程写得比别处细。

---

## 一、页码从哪来（决定锚定是真是假）

精读笔记的铁律是每个字段锚 `(p.X)`。**锚定的可信度完全取决于读 PDF 的方式**：
用一种丢掉分页信息的方式读完再回填页码，模型只能凭印象编——这正是铁律要防的事。
所以读法必须先定，不能让子 agent 自由发挥。

### 读法优先级

1. **首选：Read 工具直接读 PDF，带 `pages` 参数分段读。**
   Read 对 PDF 是按页返回的，页边界不丢，`(p.X)` 有据可查。单次上限 20 页。
   - ≤20 页的论文：一次 `pages: "1-20"`（或实际页数）读完。
   - >20 页（常见于带长附录的经济学/医学论文）：先读 `1-12` 建立骨架，
     再按需要读指定区间（如 `"25-32"` 只取附录的关键表）。不要为了"读全"
     把 60 页全部拉进上下文——附录里大段的证明和额外回归表通常不构成笔记字段。

2. **兜底：`pdftotext -layout <pdf> -`**（poppler；`brew install poppler` /
   `apt install poppler-utils`）。它在页与页之间输出换页符 `\f`——**第 N 个 `\f`
   之后的内容就是第 N+1 页**，据此换算锚点。`-layout` 不能省，否则多栏排版会
   被串成一列，表格彻底错位。

3. **两条都不通**（加密 PDF / 纯扫描件 / Read 报错）：不要硬猜。
   在笔记 Metadata 里标 `anchor-degraded`，全篇改用 `(§N.M)` 章节号锚定，
   并在回传里如实报告。降级是可接受的，编页码不是。

### 物理页 vs 印刷页

期刊 PDF 常带自己的印刷页码（比如首页就印着 1023）。规则：

- **一律用物理页码**（PDF 的第几页，从 1 开始数，也就是 Read 的 `pages` 口径）。
- 印刷页码与物理页码不一致时，在 Metadata 里记一次基准：
  `PDF 页码基准: 物理 p.1 = 印刷 p.1023`。

为什么这么定：下游读这份笔记的人（和阶段 3b 的综合、阶段 4 回传后的证据核查）
打开的是同一个本地 PDF 文件，物理页码是他们能一键跳到的坐标；印刷页码要心算。
两套页码混着用又不声明，是笔记锚点腐坏最常见的方式。

## 二、派工模板（主 agent 复制这段，逐篇替换尖括号）

**一篇论文一个子 agent**。不要为省 agent 数把两三篇塞给一个——子 agent 要同时
持有两篇全文时，留给锚定核对的注意力直接减半，而多派一个子 agent 的边际成本
远低于一篇烂笔记的代价（烂笔记会顺着 claims 污染整份报告）。

model 用 `sonnet`：单篇精读是模板填充型任务，边界清楚、有现成模板，
不需要跨篇推理能力；跨篇综合（3b）才需要更强的模型。

```
精读一篇论文，产出一份锚定到页码的结构化笔记。

## 输入
- PDF: <pd-research/<slug>/pdfs/<safe_id>.pdf>
- paper_id（笔记正文里原样写这个值，不要用文件名）: <worklist 行的 id 原样，如 arxiv:2409.10897>
- 标题: <title>
- 笔记写到: <pd-research/<slug>/notes/<safe_id>.md>

## 怎么读
1. 用 Read 工具读上面这个 PDF，带 pages 参数。≤20 页一次读完；更长的先读
   1-12 建立骨架，再按需读指定区间。
2. Read 读不了（加密/扫描件/报错）就退到 `pdftotext -layout <pdf> -`：
   换页符 \f 是页边界，第 N 个 \f 之后是第 N+1 页。
3. 两条都不通：在 Metadata 标 anchor-degraded，全篇改用 (§N.M) 章节锚，
   并在回传里说明。不要凭印象编页码。
4. 页码一律用物理页（PDF 第几页）。若论文印刷页码与之不同，在 Metadata 记一行
   基准：`PDF 页码基准: 物理 p.1 = 印刷 p.<N>`。

## 笔记怎么写
严格按 <skill 路径>/references/reading-note-template.md 的模板与规程：
- 先扫结构（abstract / intro 末段贡献列表 / conclusion / 所有图表标题）再精读；
- 图表公式随读随记，直接写进它支撑的那个字段，不要攒一个"图表"章节；
- 每写一个字段立刻标位置，不要写完回填；
- 每个字段必须有锚点 (p.X) / (p.X, Fig.Y) / (p.X, Table.Y)，最低要求 (§N.M)；
  定位不到就写"未在文中明确说明"，绝不允许无锚字段，更不允许编造锚点；
- QA 留到最后写，挑需要读过方法细节才能答的问题（5-7 个）。

## 只有摘要的情况
如果这篇没有 PDF（阶段 2 没取到），在 Metadata 首行标 `abstract-only`，
只填能从摘要确证的字段，其余写"仅摘要，无法确定"。不要用你自己的知识
补全方法细节或实验数字——这份笔记下游会被当成证据用。

## 回传给我什么（重要）
**不要把笔记正文贴回来**。笔记已经在磁盘上了，正文回传只会挤掉我做跨篇综合的
上下文预算。只回这个块：

paper_id: <id>
note_path: <路径>
depth: fulltext | abstract-only | anchor-degraded
pages_read: <如 1-14 / 1-12,25-31>
anchor_coverage: <带锚点的字段数>/<你实际填了内容的字段数>
  # 必须是「数字/数字」，如 14/16。分母 = 模板里你真正写了内容的字段数，
  # 上限 18（QA 整体算 1 个字段，不按问答对展开；写成「未在文中明确说明」
  # 的字段不计入分母）。分母 > 18 说明你在数锚点条目而不是数字段，重算。
headline:
  - <这篇最值得进综合的发现 1，一句话，带锚点>
  - <发现 2>
  - <发现 3>
unresolved: <读完仍未确定的关键点，没有就写 none>
```

**`anchor_coverage` 的分母口径**（必须给数字比值，不要写「全部字段已锚」这类话——
主 agent 要拿它做机械判断）：

- **分母** = 你**实际写了实质内容**的字段数。写成「未在文中明确说明」的字段不计入
  分母（它们是诚实的空缺，不是锚定失败）；QA 部分整体算 **1 个字段**，不按问答对数
  展开——模板允许 5-7 对，按对数算会让分母浮动、比值失去可比性。
- **分子** = 其中带了 `(p.X)` / `(p.X, Fig.Y)` / `(§N.M)` 任一锚点的字段数。
- 按这个口径，一篇正常的全文精读大约是 14-18 个字段，比值应该接近 1。低于 0.8
  说明有相当一部分内容你没能定位到出处——那正是要重派的信号。

---

## 三、回传后主 agent 做什么

1. **按 `anchor_coverage` 判重派**：比值低于 0.8、或 `depth` 与预期不符
   （fetch 账本说 `ok` 却回了 abstract-only）的，重派该篇。
   子 agent 回了话而不是数字比值（"全部字段已锚"）时，先问它要比值再判——
   这条规则的全部价值就在于它是机械的，一旦接受描述性回答就退化成了看感觉。
   **分母 > 18 也要退回重算**（实测见过 `43/43`）：那是在数锚点条目而不是数
   字段，比值恒等于 1，等于把这道闸门空转掉。
   不要想着"在 3b 综合阶段补"——综合阶段没有 PDF 在手，补出来的必然是凭印象的转述。
2. **3a→3b 的 gate**：`notes/` 的文件数 == 本轮参与深读的论文数
   （含 abstract-only 的那些，它们也要出笔记）。缺了就先补齐再综合。
3. **只把 headline + unresolved 带进 3b 的规划**，需要细节时再回读具体的
   `notes/<id>.md`。这是把 20 篇论文的深度装进一个综合上下文的唯一方式。
4. **`unresolved` 不要丢**：它们是 `claims.jsonl` 里 `gap` 状态的第一手来源，
   也是回传后服务端"发芽"成开放问题的原料（见 SKILL.md 阶段 4）。
